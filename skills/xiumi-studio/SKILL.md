# 秀米图文台工作流

这套流程是从真实任务里跑出来的：拿两份学校通稿（一份 Word 含 10 张内嵌图、一份纯文字 Word + 单独一文件夹照片）在面板里从零排到可发布。每一步都对应一个工具，跳过哪一步都会在后面付出代价。

> 已经跑通四遍真稿：①自绘版式直接进「我的图文」；②套账号内模板版（模板装饰全留、文字图片全换）；③模板版带真图（10 张真照片 + 5 个透明占位，DOM 里逐张数过 img）；④**语义排版引擎 + 真排打分**（一篇 17 段内容 / 4 张图的真稿，两张表转成四行文字，7 个模板扣分项逐条可查）。
> 第 2.5 / 6 节的每一条都有实测输出支撑；没把握的地方会标「待验」，别自己升格成经验。
> 全过程复跑记录见 `docs/E2E-R3.md`（含踩过的坑和对应修复）。

## 一句话原则

**材料是别人的，排版是你的。** 文字一个字都不能删改（可以调顺序之外的一切排版：分块、层级、留白、强调），图片一张都不能漏。你只对"看起来怎么样"和"在秀米里能不能直接看到"负责。

## 工具一览（16 个，按用途记，不要记参数）

| 用途 | 工具 |
| --- | --- |
| 看现场 | `xiumi_open` |
| 建房 | `xiumi_import_docx`（Word 一步成稿）、`xiumi_add_images`（补图/分组落位）、`xiumi_layout_images`（旧稿图片按小节重分） |
| 调版式 | `xiumi_set_theme`、`xiumi_set_block`、`xiumi_make_cover`、`xiumi_duplicate_project`（另存一版再改）、`xiumi_remove_image`（删误拖的图，连块一起） |
| 套模板 | `xiumi_template_shows`（账号里能套的模板）、`xiumi_template_apply`（复制模板再灌内容，默认干跑）、`xiumi_template_fill`（只往本插件复制出来的副本里灌） |
| 自检 | `xiumi_preview`（图数/未用素材/缺图/体积） |
| 参考 | `xiumi_templates`（秀米免费模板**目录**：只能看、不能直接套） |
| 交付 | `xiumi_publish`（先体检再投递）、`xiumi_xiumi_tools`（看真实接口 schema） |

## 0. 先看现场（每次动手前）

调 `xiumi_open`。它会给你：当前工程、块清单、主题、封面状态、面板地址。

- 有工程 → 先读块清单，再决定改哪里。**不要凭记忆改。**
- 没工程 → 走第 1 步。

面板地址要主动说给用户，那是他能实时看到你在做什么的唯一窗口。

## 1. 收材料

用户给的通常是这几种形态，处理方式不同：

| 材料形态 | 做法 |
| --- | --- |
| Word（.docx，图文混排） | `xiumi_import_docx{path}`，一步建工程 |
| Word + 图片分开发 | 先 import docx，再 `xiumi_add_images{paths:[…]}` 补图（见 1.1） |
| 纯文字 Word | 同上 import，图片为 0，靠版式与配色撑住 |
| 已经排好的秀米链接 | 不在本插件范围内，直接告诉用户这次要从材料重排 |

导入后立刻核对两件事，用 `xiumi_preview`：

1. **图片数对不对**（`图 N` 应等于 docx 里内嵌图片数；有未用上的素材它会警告）
2. **结构对不对**（标题/导语/小标题/正文/结尾是否分对了）

分错了就用 `xiumi_set_block` 调，不要回去改 Word。

### 1.1 补图（图片和文字分开发时）

`xiumi_add_images` 收 `paths: string[]`，每一项可以是单张图，也可以是整个文件夹（文件夹按文件名自然序展开：1,2,…,10）。它只增不减、不覆盖已有素材，编号重名自动加 -2。

- **默认位置**是文末（没有 END 块就追加在最后）。整篇图都该落在同一个位置时才这样用。
- 要让图跟着小节走，就**分组多次调用**，用 `after` 指定"插在哪一块之后"：先 `xiumi_open` 拿到块 id，再 `{paths:[…该小节的图…], after:'b17'}`。
- 落到哪一块之后属于排版判断，但**把合影放进"领导致辞"底下这类错位是硬伤**；拿不准就问用户"这几张分别对应哪个环节"。
- 图片一张都不能漏：补完立刻 `xiumi_preview`，看两个数字——`图 N` 等于材料图数、且不报"未用上的素材"。
- 已经排好的旧稿（图全堆在文末）不用手工搬：面板「图片按小节分」/ `xiumi_layout_images` 会按现有小节重新分配、顺序不变。
- 用户自己也能补：面板右栏「素材」有拖拽区，顶栏（含右侧栏窄版）有「补图」按钮，拖进去就等于替他做了同一件事。他补完你 `xiumi_open` 重读一次即可，别重倒一遍。

## 2. 定主题

导入时已按标题关键词自动挑了一套。你要做的是判断它合不合内容气质：

- 红色主题、党建、纪念、思政、烈士 → zhusha 朱砂
- 学术讲座、教研、论坛、读书 → qingci 青瓷
- 工作部署、换届、总结、通知、公示 → molan 墨蓝
- 招新、社团、文艺、晚会、节日、运动会 → yingfen 樱粉
- 内容本身就是文字（书评、散文、长论述）→ subai 素白

不合就 `xiumi_set_theme`，换完**必须重绘封面**（`xiumi_make_cover`），否则封面还是旧配色，一眼就露馅。

想找参考版式：`xiumi_templates{q:'党建'}` 会列秀米免费模板（标题 / 作者 / 被复制次数 / 预览链接），用来判断这个题材的公开成品偏什么气质、配什么色；**只做参考**，不会把成品塞进模板本体（秀米不开放这种写入）。面板右栏也有同一份「参考模板」列表。

## 2.5 套真模板（要"模板自带的背景/装饰/组件/动效"时走这条）

两条路，先认清代价：

| 路 | 成品长相 | 代价 |
| --- | --- | --- |
| 自绘（§2 + §3） | 我们排的版式，配色/封面/分隔是我们自己的 | 没有任何秀米模板组件；但完全可控 |
| 套模板（本节） | 模板的骨架、装饰、动效原样保留，只换文字与图片 | 只能套**账号里已有的**模板作品 |

### 2.5.1 哪些模板能套（这条最容易想当然）

秀米**不开放**「把任意免费模板写进别人账号」：

- 模板目录里每条都有 `editUrl: /studio/v5#/paper/for/736997926` 这样的 show_id，看着能直接用——**用不了**。
  `copy_show({show_id:736997926})` 返回 `Common:Failed_DataNotMatch`；`get_show_edit_spec(736997926)` 返回 `Failed_NotFound`。
- 能套的只有：**这个账号里已经「使用模板」另存过的作品**。用 `GET /xiumi/api/template/shows` 列，判据是图片槽 ≥12 且文字槽 ≥8。

要套目录里的新模板 → 必须在**登录态的 DSH 浏览器**里点一次「使用模板」，它才会出现在「我的图文」，之后程序接管。
**不要**为了省这一步去伪造 show_id 或猜接口。

### 2.5.2 填槽四条硬规则（都是撞了墙才写下来的）

1. **文字槽不能绑空串/空格/换行**：`{"valid":false,"errors":[{"code":"MATERIAL_EMPTY_TEXT","slot":"body_17"}]}`。
   要清空一个槽只能用**零宽空格 U+200B**（`\u200b`），实测 `{"valid":true,"errors":[]}`。
2. **图片槽可以绑任意图床 URL**；用 **1×1 透明 PNG** 顶掉模板自带的照片，图片不够时多余的槽这样占位。
3. **spec 的 `S image_1..13 IMG` 是 13 个独立槽**，必须展开成 image_1…image_13 逐槽寻址；只绑 image_1 会漏 12 张。
4. **没绑的槽保持原样**——模板的装饰、留白、动效就靠这个活下来。不要"顺手"把全部槽都清一遍。

### 2.5.3 挑哪个模板（不要凭感觉）

调 `xiumi_template_apply {project_id}`（**不给 show_id** 就会自己挑；等同 `POST /xiumi/api/template/apply`），它按两件事打分并回 `picked.reasons`：

打分口径（按权重从重到轻，`picked.reasons` 会逐条写出来）：

1. **真排一遍**（`planLayout` 拿这份稿子在模板里真排一次，2026-11-15 新加，最可靠）：
   - **空着的小节标题槽**：每个 −2（最多 −10）。空槽在成品里是**带边框的空白面板**，最难看的就这个；
   - **有段落塞不下、被并进最后一个正文槽**：每段 −2（最多 −8）。这就是用户说的「长段生硬插入」；
   - **空着的图片槽**：每个 −1（最多 −6），空槽会露模板底色块；
2. **正文槽够不够**：够 +2；不够每缺 1 段 −1（最多 −8）；
3. **题材词命中** +2：从标题 + 小节标题抽词（会议/部署/总结/换届/喜报/讲座/文艺/旅行…）和模板标题对；
4. **超大标题槽**（`fs ≥ 1.45`）每个 −1（最多 −4）：字号均匀的模板优先；
5. 没有小节槽 −3；没有大标题槽 −2；
6. 已发布的 −1（多半是成品，不是给人套的模板）。

**账号里的成品不会出现在候选里**：套过模板的作品槽位形状和模板一模一样，光看形状分不出来，所以先按标题认亲、再按**正文认亲**（模板槽里的 `ex` 原文能在本地工程正文里命中 ≥2 条 → 判为成品，跳过）。

所以**不要**挑槽位远超需求的模板（比如 73 个图位给 10 张图，成品会空一大片）。挑完把理由说给用户听——尤其「会留下 N 个空标题框」这种，要提前说，别等他自己看见。

两条选型时看不出来、只有干跑才露的本性（都要转告用户，别自己闷着）：

- **超大标题槽**：模板里字号 `fs ≥ 1.45` 的槽本来是「一句话大标题」，你把 60 字以上的长段落塞进去，它会变成一屏大蓝字（一次真稿的 body_2 就是这样）。干跑会警告"模板有 N 个超大标题槽…"。要么接受这个效果并说清这是模板设计，要么换字号均匀的模板——**不要去改稿子来迁就模板**。
- **图不够就是透明占位**：模板 15 个图位、你 10 张图，剩下 5 个会被 1×1 透明图顶掉（模板自带照片不会留下）。这是对的：宁可留白也不能让模板的照片混进我们的稿子。

### 2.5.4 顺序

1. `xiumi_template_apply {project_id, show_id?, dry_run:true}`（或 `POST /xiumi/api/template/apply`）→ 看 `bindings`、`warnings`、`report`。
   干跑**零副作用**：不 `copy_show`、也不往图床传透明图（用进程内已缓存的那张地址）。早期版本干跑也会复制，账号里会堆垃圾稿（已修）。
   警告要逐条读，尤其这六条：「有 N 张图还只在本地、没进秀米图床」（成品只有 M 张能显示）、「模板还有 N 个空图片槽」「文字段落比模板槽位多」「超大标题槽」、「标题超过 work_title 槽的 60 字上限」「摘要槽只放前 120 字」（后两条是**截断**：正文里仍是全文，但摘要会短一截，要说给用户）。
   接口直接回 `{ok:false,error:'套模板失败：模板 spec 有问题：…'}` 时不要重试硬灌：先 `get_show_edit_spec` 重新取一次 spec（没有 `spec_version`、区间起止反了、区间超过 999 个，都会被这一道闸挡住）。
2. 同接口 `dry_run:false` → 真跑。它先把你工程里**只在本地**的图传进秀米图床，再 `copy_show` 复制一份模板改（原模板不动），返回 `showId` 与 `editUrl`。
   - 真跑失败会**自己把复制出来的空稿删进回收站**：这时 `showId` 为 `null`、`cleanedShowId` 有值，`warnings` 里那句「已把复制出来的那篇空稿删进回收站」要原样告诉用户。
   - `title_postfix` 最多 **8 个字**（秀米 `copy_show` 硬限制，超了整次复制 400）。宿主已裁，工具 schema 也是 8。
3. 复核：`get_show_edit_spec(新作品号)`，抽两个槽确认是这篇的文字；未绑槽应与模板逐字节相同。
4. 干跑/真跑的输出都要说给用户：几个槽、几张图、什么警告。
5. **图片有没有真进去，spec 看不出来**：图片槽是 `S image_1 IMG role:image opt`，桩模板里根本没有 `ex:` 载荷，
   绑完再读 spec 仍然是空。要看有没有生效，按可信度排：
   1. `update_show_from_plan` 回的 `updated_slots` 里有没有对应 image_N，且数量等于绑定的槽数（宿主会判，不够就报错）；
   2. 拉预览页的**渲染后 DOM** 数图（实测可用）：
      `"msedge.exe" --headless=new --dump-dom "<preview_url>" > dom.html`，再
      `grep -oE '//img\.xiumi\.us/[^"&<> ]+' dom.html | sort | uniq -c`——10 张真图各 1 条、5 个空槽都是同一个 `…-sz_70.png`（透明图），
      且**不该**出现模板自己的 `statics.xiumi.us/…/i/…` 照片；
   3. 截图肉眼过一遍（`--screenshot=out.png --window-size=430,2400 --virtual-time-budget=12000`）。
   别因为 spec 里看不见就说"没绑上"。

### 2.5.5 语义排版引擎：字是怎么被放进槽里的

引擎在 `host/layout.mjs`（`collectUnits` → `planLayout`）。它先把稿子拆成**内容单元**，再按单元类型找角色对得上的槽，不再「按顺序一个个填」。这是「标题页里塞着正文」那个老问题的根治。

| 内容单元 | 优先落的槽 | 说明 |
| --- | --- | --- |
| `title` 标题 | `title`（字号 0.99–1.6） | **>22 字的长标题分层找槽**：① 0.99–1.6 的 title 槽 ② 同字号的小节/正文槽 ③ ≤1.6 的 title 槽 ④ ≤1.6 的小节/正文槽；实在没有再进大标题槽并警告。长标题进 2.5 倍大槽会排成一屏巨字，必须避开 |
| `lead` 导语 | `body` / `lead` | 一段，进正文槽 |
| `paragraph` 正文 | `body` | 一段一槽，找不到就报「塞不下」 |
| `section` 小节标题 | `section` | 没有小节槽时才退到正文槽并警告 |
| `table` 表格 | `body` | **数据只有 1 行且列数 ≤6 时转置成「表头：值」多行**，别拼成一条长龙（会溢出画外） |
| `signature` 署名 | `body` / `section` | 常见是「撰稿／初审／终审」三行 |
| 编号槽 | 只放模板自己的 `01/02` | 稿子没有小节序号就把编号槽留空，**绝不把正文塞进大数字里** |

图片单独成表，按「文字走到哪」分配位置。**一张照片只用一次，绝不重复**（用户 2026-11-15 的第 2 版要求：宁可有空槽，也别为填满模板把同一张图放十遍——那是「为模板服务」而不是「为内容服务」）：

- **图多于槽**：按顺序一一对应，多出来的图必须警告「图片比模板图片槽多（N > M），有 K 张放不进去」；
- **图少于槽**：图按顺序**均匀摊到整篇**的槽上（首图别全堆在开头，末图也别只在结尾），其余槽用 1200×2 的透明细线 PNG 顶掉——既不重复用图，也不让模板自带的照片留在成品里；
- 空图槽在成品里通常缩成一条细线，基本看不见；真正会露出来的是**空的小节标题槽**（模板给的浅灰卡片），见 §6.5。

图比槽多时无解，图比槽少时也别硬凑：用户宁可看到留白，也不想看到同一张图刷屏。

没被用到的文字槽一律填**零宽空格 U+200B**（模板占位文案不能留，空串又会被 `MATERIAL_EMPTY_TEXT` 挡）。

干跑和真跑的警告文案不一样，别混：

- 干跑（不传图）：「干跑不传图，所以 N 个图片槽现在是空的；真跑时会先把 M 张本地图传进秀米图床」；
- 真跑有图但槽更多：「模板有 N 个图片槽，稿子里只有 M 张图：每张图只用一次，剩下的 K 个槽会用透明细线占位（不重复用图，也不留模板自带的照片）」。

## 3. 调排版（允许 / 禁止）

允许：

- 拆块与合并（把一长段拆成两段读起来更顺，或把小标题单独成 section）
- 上下移动块的顺序（只在明显更顺时；**大幅改动原稿叙述顺序要先问人**）
- 给图片加图注（`caption`）：只写客观信息（"讲座现场"、"与会人员合影"），不编造人物姓名、职务、时间、地点
- 小标题编号、kicker 小标眉（不确定就不写，别编）。**编号由导入器统一加**：原稿自己带"01 / 一、"的会被抽出来当编号、正文里不再重复；"结语 / 后记"这类收尾小标题故意不带序号。看到编号是空的不算 bug，别自己去补。
- 强调、留白、分隔线、结尾装饰

禁止：

- 删除、缩写、改写文稿的句子（错别字和多余空格可以清，改完要在回复里说明改了什么）
- 编造材料里没有的事实（到场人数、领导姓名、引语、日期）
- 漏图、重复用同一张图充当不同内容
- 把图片说明写成抒情文案（图注是信息，不是宣传）

## 4. 封面

`xiumi_make_cover` 生成 900×383 封面 + 500×500 方图，配色跟随主题，标题自动换行。

- 标题超过 2 行会自动降字号，降到底还挤 → 说明标题太长，这时**不要改标题**，让它在封面里按 2 行断句更合理的方式重排（只调断行，不动字）。
- 换主题后重绘；改了标题（只允许在明确授权下）也要重绘。

## 5. 自检（发布前必做，不许跳）

逐条对照，缺一条就不许发布：

1. `xiumi_preview` 里 **图 N 等于材料图数**，且没有"未用上的素材"警告（面板「素材」应显示 `N / N 用上`，出现红字「未用上」就是漏了）
2. 正文块里**没有丢段**：导入时的块数 ± 你主动的调整，能说清每一处增减
3. 文稿文字与原稿逐段可对：没有整句被改写
4. 手机宽度下没有横向滚动、没有一屏全是字（打开面板自己看）
5. 主题与内容气质一致，封面配色与正文一致
6. 结尾有落款/编辑信息（学校通稿通常需要，材料里没有就问用户要不要加）

## 6. 发布到秀米「我的图文」

> 这一节是**跑通之后写的**：2026-11-15 用一篇真实的会议通稿（年度工作部署会）走完全程，成品直接出现在秀米「我的图文」里，
> 编辑页形如 `https://xiumi.us/studio/v5#/paper/for/<作品号>`，`get_shows` 能查到保存时间。

### 6.1 真实链路（照这个顺序走，不要自由发挥）

1. **自检**：先过 §5 六条。图数不对、有素材没用上，停在这里，别往发布走。
2. **图片进秀米图床**：`xiumi_publish` 内部逐张调 `create_image`（base64 或 url），拿回 `//img.xiumi.us/xmi/...` 这种**协议相对地址**，插件会补成 https 再落进块里。实测 10 张全成。
3. **渲染**：`renderFragment(project, { preferRemote: true })`，HTML 里每个 `<img>` 都是图床 CDN 地址（不是 127.0.0.1，也不是 base64）。这一步不成立，粘出来的图会裂。
4. **投递**：秀米 MCP 的 12 个工具里**没有新建图文**（`create_show_from_plan` / `create_show` 直接调都返回 `-32602 Tool not found`，而 `get_show_edit_spec` 能报缺参数）。所以程序投递这一步**注定失败**，会返回 `ready` + 一句提示，这是设计好的结果，不是 bug。**不要为了让它"成功"去猜别的工具名。**
5. **落地（人只按一下）**：面板「发布到我的图文」→ 面板会自动①把内联样式 HTML 放进剪贴板 ②打开 https://xiumi.us/#/studio/papers ③顶部黄条写着三步。人只需：新建一个图文 → 光标点正文区 → `Ctrl+V` → `Ctrl+S`。标题一般随粘贴带进来；没带就手打。
6. **回执**：`get_shows` 复核 `show_id` / `title` / `saved_at`；打开 `preview_url` 在浏览器里看一眼（**这个预览页是纯 JS 壳，curl 只能拿到壳，不能当证据**）。

### 6.2 什么会自动做，什么必须人做

| 环节 | 谁做 | 说明 |
| --- | --- | --- |
| 图床上传 | 程序 | create_image，返回的协议相对地址由插件规范化 |
| HTML 生成 / 剪贴板 | 程序 | 与预览、导出同一份 renderFragment，逐字节一致 |
| 打开「我的图文」 | 程序 | 与你点击同一个手势里开窗，避免被拦 |
| 新建图文 / 粘贴 / 保存 | 人 | 跨页注入粘贴事件浏览器不接受；不要假装按了 |
| 授权 | 人 | 一次即可，凭证在 `~/.dsh/xiumi/oauth.json` |

### 6.3 出错时怎么说话

- **未授权**：让用户点顶栏胶囊（已连接时会显示「秀米」两个字，不是「连接秀米」）→ 登录并同意。之后 1.5 秒轮询会自动连上。
- **图床上传有失败**：点名是哪几个文件、什么错误；不要带着本机地址去发布。
- **接口报错**：错误里带真实工具清单。连续两次失败就停下来说卡在哪 + 给剪贴板兜底，别耗在猜参数上。

### 6.4 如果这篇是套模板出来的（§2.5）

那就**不需要**剪贴板这一步：`template/apply` 真跑完，作品已经在「我的图文」里了（`copy_show` 直接建）。
剩下的只是把它打开给人看 + 让标题对：

1. 报出作品号与编辑页 `https://xiumi.us/studio/v5#/paper/for/<show_id>`；
2. 标题槽（`work_title`）已随填槽换过，若模板限制长度（`max60`）导致截断，如实说；
3. 想在微信里看最终样子，仍需人在登录态编辑器里点一次「预览」——未发布作品的公开预览恒 403 `Camus:Failed_ShowRelease`，别把这个 403 当成我们做错了。

离线方案同样算交付：图文在秀米编辑器里能看到、能保存，就满足"在我的图文里看到"的实质要求。
### 6.5 成品验收：700 宽截图法（一定要用这个宽度）

```
node _inspect/shot-only.mjs <showId> 700 9000      # 截图路径必须绝对路径
python _inspect/slice-image.py _inspect/preview/tpl-<showId>-700.png <outDir> 8
```

- **必须 700 宽**：430/375 宽截图会把 700+ 宽的版面从右边裁掉，看着像「文字被切断」，那是截图的问题，不是排版坏了。图上见到「右边被切」先怀疑宽度。
- 逐片核对清单：标题字号 → 日期 → 模板装饰带/编号 → 每个正文段是否成段 → 每张图是否出现且不糊 → 表格是否成行 → 小节标题是否成条 → 署名三行。
- 用 `--virtual-time-budget=25000` 等字体和图加载完，否则会拍到半截。

已知残留（不是 bug，是「槽比稿子多」的硬约束，要在交付时说明）：

- **空的小节标题框**：账号里没有「正文槽 ≥ 15 且小节槽 ≤ 2」的模板时必然出现（一篇真稿就有 2 个）。打分已经把它们压到最低分；
- **空的大标题卡**：36 字长标题按规则避开 2.5 倍大槽，那个大槽就空着，露出模板白卡底。

### 6.6 绝不要做的两件事

1. **绝不对「已经灌过内容」的副本再灌一次**。`spec` 是从副本自己取的，槽里的占位文案已经变成我们的正文，`classifySlot` 会据此把角色判错（实测 section 槽从 4 个被算成 9 个，「空标题框」从 2 变成 8，排版跟着乱）。要改策略就**回到原模板重新复制 + 灌**，旧副本删进回收站。
2. **绝不为了让「没有新建图文接口」这件事成功去猜工具名**（见 §6.1 第 4 条）。套模板这条路本身就能把作品直接建进「我的图文」，不需要剪贴板。

## 7. 交付话术

只讲人需要知道的：这篇的主题与配色理由、块结构、图都落在哪、封面在哪、发布结果、以及任何你替他做过的判断（图注、编号、分隔）。

不要复述工具输出，不要贴 HTML。

## 与用户沟通的三条硬规矩

1. **材料缺什么就问什么**，不要用想象补齐（缺图、缺日期、缺落款）。
2. **大幅改结构先问**，小幅调排版直接做并说明。
3. **每一步都能在面板里看见**——动手前后都提一句面板地址，人随时能打断你。
